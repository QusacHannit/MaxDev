================================================================================
                  MAXDEV — ИНСТРУКЦИЯ ПО РАЗВЁРТЫВАНИЮ
================================================================================

Эта инструкция объясняет, как правильно разместить фронтенд, бэкенд и базу
данных MaxDev на продакшн-сервере. Инструкция подходит для:
  - VPS/VDS (DigitalOcean, Hetzner, Linode, Selectel, Beget и т.д.)
  - Облачных серверов (Yandex Cloud, Timeweb, Timeweb Cloud, Aeza и т.д.)
  - Любого Linux-сервера с Ubuntu 22.04+ или Debian 11+

================================================================================
  1. ВЫБОР СЕРВЕРА И ПОДГОТОВКА
================================================================================

  Минимальные требования к серверу:
  - 1 CPU, 1-2 GB RAM, 20+ GB SSD
  - ОС: Ubuntu 22.04 LTS или Debian 11+
  - Открытые порты: 80 (HTTP), 443 (HTTPS), 22 (SSH)

  Рекомендация:
  - Для начала подойдёт VPS за 300-500 руб/мес (1vCPU, 2GB RAM)
  - Домен купить на любом регистраторе (Reg.ru, Nic.ru и т.д.)

  Подготовка сервера:
  1. Подключитесь по SSH:
       ssh root@ваш-ip-адрес

  2. Обновите систему:
       apt update && apt upgrade -y

  3. Установите базовые утилиты:
       apt install -y nginx certbot python3-certbot-nginx git curl

  4. Создайте пользователя для проекта:
       adduser maxdev
       usermod -aG sudo maxdev
       su - maxdev

================================================================================
  2. ГДЕ РАЗМЕСТИТЬ ФРОНТЕНД, БЭКЕНД И БАЗУ ДАННЫХ
================================================================================

  На одном VPS-сервере можно разместить ВСЁ:

  ┌─────────────────────────────────────────────────────────────────┐
  │                    ОДИН СЕРВЕР (VPS)                            │
  │  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐  │
  │  │   NGINX      │  │   FRONTEND   │  │   BACKEND + БАЗА     │  │
  │  │ (обратный    │  │  (React,     │  │  (Python, Flask,     │  │
  │  │  прокси)     │  │   Vite)      │  │   SQLite)            │  │
  │  └──────┬───────┘  └──────┬───────┘  └──────────┬───────────┘  │
  │         │                 │                      │              │
  │  :80, 443            :5173 (dev)            :5000 (prod)        │
  │                       или собранные          + SQLite файл      │
  │                       статику (build)                            │
  └─────────────────────────────────────────────────────────────────┘

  Вариант А — один сервер (рекомендуется для начала):
  - Nginx на портах 80/443
  - Бэкенд на порту 5000 (через gunicorn)
  - Бэкенд + база данных на том же сервере (SQLite)
  - Фронтенд — либо собранная статика через Nginx, либо на порту 5173

  Вариант Б — раздельные серверы (для масштабирования):
  - Сервер 1: Nginx + фронтенд (собранные файлы)
  - Сервер 2: бэкенд + база данных
  - На сервере 1 настройте Nginx прокси на сервер 2

================================================================================
  3. НАСТРОЙКА BACKEND (СЕРВЕР)
================================================================================

  3.1 Загрузите код бэкенда на сервер:
      cd ~
      git clone https://github.com/ваш-репозиторий/maxdev-backend.git
      cd maxdev-backend

  3.2 Установите Python-зависимости:
      python3 -m venv venv
      source venv/bin/activate
      pip install -r requirements.txt

  3.3 Создайте .env файл в backend/:
      nano .env

      Содержимое .env:
      ┌──────────────────────────────────────────────────────────┐
      │ JWT_SECRET_KEY=сгенерируйте-длинный-случайный-ключ       │
      │ FRONTEND_URL=https://ваш-домен.ru                        │
      │ SMTP_HOST=smtp.gmail.com                                 │
      │ SMTP_PORT=587                                            │
      │ SMTP_USER=ваш-email@gmail.com                            │
      │ SMTP_PASSWORD=пароль-приложения-google                   │
      │ SMTP_FROM=MaxDev <ваш-email@gmail.com>                   │
      │ YOOKASSA_SHOP_ID=ваш-shop-id                             │
      │ YOOKASSA_SECRET_KEY=ваш-secret-key                       │
      └──────────────────────────────────────────────────────────┘

      Сгенерировать JWT ключ:
      python -c "import secrets; print(secrets.token_hex(32))"

  3.4 Инициализируйте базу данных:
      python init_db.py

      Файл базы данных появится в:
      backend/instance/maxdev.db

  3.5 Настройте gunicorn (продакшн-сервер Python):
      pip install gunicorn

      Создайте файл gunicorn.conf.py:
      nano gunicorn.conf.py

      Содержание gunicorn.conf.py:
      ┌──────────────────────────────────────────────────────────┐
      │ bind = '127.0.0.1:5000'                                  │
      │ workers = 2                                              │
      │ timeout = 120                                            │
      │ accesslog = '/home/maxdev/logs/access.log'               │
      │ errorlog = '/home/maxdev/logs/error.log'                 │
      │ access_log_format = '%(h)s %(l)s %(u)s %(t)s "%(r)s" ...'│
      └──────────────────────────────────────────────────────────┘

  3.6 Создайте systemd-сервис для автоматического запуска:
      sudo nano /etc/systemd/system/maxdev-backend.service

      Содержание maxdev-backend.service:
      ┌──────────────────────────────────────────────────────────┐
      │ [Unit]                                                   │
      │ Description=MaxDev Backend API                           │
      │ After=network.target                                     │
      │                                                          │
      │ [Service]                                                │
      │ User=maxdev                                              │
      │ Group=www-data                                           │
      │ WorkingDirectory=/home/maxdev/maxdev-backend             │
      │ ExecStart=/home/maxdev/maxdev-backend/venv/bin/gunicorn  │
      │         -c gunicorn.conf.py app:app                      │
      │ Restart=always                                           │
      │ RestartSec=5                                             │
      │                                                          │
      │ [Install]                                                │
      │ WantedBy=multi-user.target                               │
      └──────────────────────────────────────────────────────────┘

      Включите сервис:
      sudo systemctl daemon-reload
      sudo systemctl enable maxdev-backend
      sudo systemctl start maxdev-backend
      sudo systemctl status maxdev-backend

================================================================================
  4. НАСТРОЙКА FRONTEND (ФРОНТЕНД)
================================================================================

  Вариант А — Собранные файлы через Nginx (рекомендуется):

  4.1 Соберите фронтенд:
      cd ~/maxdev-frontend
      npm install
      npm run build

      Собранные файлы будут в папке:
      dist/

  4.2 Настройте Nginx:
      sudo nano /etc/nginx/sites-available/maxdev

      Содержание конфигурации Nginx:
      ┌──────────────────────────────────────────────────────────┐
      │ server {                                                 │
      │     listen 80;                                           │
      │     server_name ваш-домен.ru www.ваш-домен.ru;           │
      │                                                          │
      │     root /home/maxdev/maxdev-frontend/dist;              │
      │     index index.html;                                    │
      │                                                          │
      │     location /api {                                      │
      │         proxy_pass http://127.0.0.1:5000;                │
      │         proxy_set_header Host $host;                     │
      │         proxy_set_header X-Real-IP $remote_addr;         │
      │         proxy_set_header X-Forwarded-For $proxy_add...; │
      │         proxy_set_header X-Forwarded-Proto $scheme;      │
      │     }                                                    │
      │                                                          │
      │     location / {                                         │
      │         try_files $uri $uri/ /index.html;                │
      │     }                                                    │
      │ }                                                        │
      └──────────────────────────────────────────────────────────┘

      Включите конфигурацию:
      sudo ln -s /etc/nginx/sites-available/maxdev /etc/nginx/sites-enabled/
      sudo nginx -t
      sudo systemctl restart nginx

  4.3 Настройте SSL (HTTPS):
      sudo certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru

  Вариант Б — Отдельный сервер для фронтенда:
  - Загрузите собранные файлы в /var/www/maxdev/
  - Настройте Nginx прокси на бэкенд-сервер
  - Настройте SSL

  5. НАСТРОЙКА ПОЧТЫ (EMAIL)
================================================================================

  Для отправки писем при регистрации и сбросе пароля:

  Вариант А — Gmail (бесплатно):
  1. Включите двухфакторную аутентификацию в Google
  2. Перейдите в Google Account → Безопасность → Пароли приложений
  3. Создайте пароль приложения для "Почта"
  4. Вставьте в backend/.env:
     SMTP_HOST=smtp.gmail.com
     SMTP_PORT=587
     SMTP_USER=ваш@gmail.com
     SMTP_PASSWORD=пароль-приложения
     SMTP_FROM=MaxDev <ваш@gmail.com>

  Вариант Б — Yandex 360:
     SMTP_HOST=smtp.yandex.ru
     SMTP_PORT=587
     SMTP_USER=ваш@yandex.ru
     SMTP_PASSWORD=пароль-приложения

  Вариант В — Mail.ru:
     SMTP_HOST=smtp.mail.ru
     SMTP_PORT=587
     SMTP_USER=ваш@mail.ru
     SMTP_PASSWORD=пароль-приложения

  Вариант Г — SMTP сервер хостинга (Beget, Timeweb и т.д.):
     SMTP_HOST=smtp.ваш-хостинг.ru
     SMTP_PORT=465
     SMTP_USE_SSL=true
     SMTP_USER=ваш-email
     SMTP_PASSWORD=пароль

  Настройте SPF/DKIM домена в DNS, чтобы письма не попадали в спам:
  SPF: v=spf1 include:_spf.your-hosting.com ~all

  6. РЕЗЕРВНОЕ КОПИРОВАНИЕ
================================================================================

  Автоматическое резервное копирование базы данных:

  6.1 Создайте скрипт бэкапа:
      nano /home/maxdev/scripts/backup-db.sh

      Содержание backup-db.sh:
      ┌──────────────────────────────────────────────────────────┐
      │ #!/bin/bash                                              │
      │                                                          │
      │ BACKUP_DIR="/home/maxdev/backups"                        │
      │ DB_FILE="/home/maxdev/maxdev-backend/instance/maxdev.db" │
      │ DATE=$(date +%Y%m%d_%H%M%S)                              │
      │                                                          │
      │ mkdir -p $BACKUP_DIR                                     │
      │ cp $DB_FILE $BACKUP_DIR/maxdev_backup_$DATE.db           │
      │                                                          │
      │ find $BACKUP_DIR -name "maxdev_backup_*.db" -mtime +30   │
      │   -delete                                                │
      └──────────────────────────────────────────────────────────┘

      chmod +x /home/maxdev/scripts/backup-db.sh

  6.2 Настройте cron для ежедневного бэкапа:
      crontab -e

      Добавьте строку:
      0 3 * * * /home/maxdev/scripts/backup-db.sh

      Это будет создавать бэкапы каждый день в 3:00 и удалять старые
      (старше 30 дней).

================================================================================
  10. РАСПРЕДЕЛЁННОЕ РАЗВЁРТЫВАНИЕ (для масштабирования)
================================================================================

  Для больших нагрузок можно разделить компоненты:

  Сервер 1 — Фронтенд + Nginx:
  - Nginx на портах 80/443
  - Собранные файлы фронтенда в /var/www/maxdev/
  - Nginx прокси на /api → Сервер 2

  Сервер 2 — Бэкенд + База данных:
  - Gunicorn на порту 5000
  - SQLite база данных на том же сервере

  Конфигурация Nginx на Сервере 1:
  ┌──────────────────────────────────────────────────────────┐
  │ location /api {                                          │
  │     proxy_pass http://ip-сервера-2:5000;                 │
  │     ...                                                  │
  │ }                                                        │
  └──────────────────────────────────────────────────────────┘

  При очень большой нагрузке можно вынести базу данных на
  отдельный сервер, но SQLite работает хорошо до ~100K
  запросов/день. Для больших нагрузок рассмотрите PostgreSQL.
